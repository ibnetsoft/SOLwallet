# AoiWallet 지갑 기능 정리

## 🏗️ 아키텍처 개요
- **네트워크**: Solana 메인넷
- **DEX 연동**: Manifest (온체인 오더북 DEX)
- **거래 페어**: 모든 토큰은 **USDT**와 페어링 (USDC 사용 안 함)
- **백엔드**: NestJS (Supabase DB), Docker 배포 (AWS EC2)
- **프론트**: Next.js (Telegram Mini App)
- **한 지갑 주소로 모든 토큰 수신 가능**: SOL, USDT, USDC, 커스텀 토큰 모두 동일 주소로 입금 (ATA 자동 생성)

---

## 👛 지갑 관리

| 기능 | 내용 |
|---|---|
| 지갑 생성 | Solana Keypair 생성, **12단어 BIP-39 니모닉** 제공 |
| 지갑 임포트 | **12단어 또는 24단어** 시드 구문으로 복원 |
| 최대 지갑 수 | **3개** (유저당) |
| 활성 지갑 전환 | 여러 지갑 생성 후 하나씩 활성화 가능 |
| 지갑 삭제 | 서버 + 로컬에서 모두 삭제 (마지막 1개는 삭제 불가) |
| 서버 동기화 | 로컬 우선 렌더 후 백그라운드에서 서버와 동기화 |
| 보안 | 개인키는 서버에 저장 안 됨 — 클라이언트에서만 보관 |

## 🔐 보안

| 항목 | 내용 |
|---|---|
| PIN 길이 | **최소 6자리** |
| 암호화 | **AES-256-GCM** + **PBKDF2** (600,000 iterations, OWASP 2023 권장) |
| 키 저장 | 암호화된 blob을 localStorage에 저장 (서버에는 없음) |
| 자동 잠금 | **5분** 무 활동 시 자동 잠금 |
| 탭 전환 잠금 | 브라우저 탭 백그라운드 전환 시 즉시 잠금 |
| 키 제로화 | 잠금 시 메모리의 개인키 버퍼(ArrayBuffer 포함) **전체 0으로 덮어씀** |
| 서명 | 모든 트랜잭션은 **온디바이스 서명** (서버는 개인키를 절대 보지 못함) |
| 니모닉 | 생성 시 한 번만 표시 (기본 마스킹), 클립보드 복사 시 **30초 후 자동 삭제** |
| 교차 기기 | 다른 기기에서 생성한 지갑은 잠금 해제 불가 (encrypted blob 없음) → 시드 구문 재임포트 필요 |
| 인증 | Telegram Mini App JWT (7일 만료), 어드민 별도 인증 |

## 💸 출금 (Withdraw)

### 코인 선택 방식
출금 시 **토큰을 먼저 선택**하는 2단계 UI:
1. **토큰 선택 화면**: 보유 토큰 목록 + 잔액 표시 → 토큰 선택
2. **출금 입력 화면**: 수신 주소 + 수량 입력 → PIN → 서명 → 제출

지원 자산: **SOL, USDT, USDC, 커스텀 토큰** (모든 Solana 네트워크 기반)

### SOL 출금
| 항목 | 내용 |
|---|---|
| 최소 출금액 | **0.001 SOL** (잔액에서 0.001 SOL은 수수료/rent 확보용으로 남겨야 함) |
| 새 주소 출금 | 수신 주소가 0 lamports이면 **최소 0.001 SOL 이상** 필요 (rent exemption) |
| **새 주소 자동 감지** | ✅ 출금 모달에서 수신 주소 입력 시 **실시간 체크** — 새 주소면 노란색 경고 "최소 0.001 SOL 이상 출금 필요" 자동 표시 |
| 잘못된 주소 | 빨간색 에러 "올바른 Solana 주소 형식이 아닙니다" 실시간 표시 |
| 최대 출금 | `보유 SOL - 0.001` (MAX 버튼이 이 값으로 설정) |
| 표시 소수점 | 잔액은 **6자리**, 거래 내역 금액은 **5자리** |
| 체인 확인 | `skipPreflight: true` → `confirmTransaction`으로 블록 포함 확인 |

### USDT / SPL 토큰 출금
| 항목 | 내용 |
|---|---|
| 최소 출금액 | **1 unit** (1 USDT, 1 USDC 등 — rent exemption 불필요, 토큰 전용) |
| 최대 출금 | **전액 출금 가능** (SOL과 달리 수수료 분리 불필요) |
| 네트워크 수수료 | 토큰 전송 tx 수수료(~0.000005 SOL)는 **송신자 SOL 잔액**에서 차감 |
| SOL 잔액 부족 시 | "SOL 잔액이 부족하여 토큰을 전송할 수 없습니다 (네트워크 수수료 필요)" 경고 |
| 수신자 ATA | 수신자에게 해당 토큰의 ATA가 없으면 **자동 생성** (트랜잭션에 포함) |

### 공통
| 항목 | 내용 |
|---|---|
| 출금 내역 | DB `transfers` 테이블에 자동 저장 (tx 해시 포함) |
| 서명 | 온디바이스 서명 (legacy Transaction) |
| 서버 | 잔액 검증 후 RPC 전송 + on-chain 컨펌 확인 |

## 📊 거래 (Trade) — Manifest DEX

| 항목 | 내용 |
|---|---|
| 거래소 | **Manifest** (Solana 온체인 오더북 DEX) |
| 거래 페어 | **토큰 / USDT** (SOL/USDT 포함) |
| 주문 유형 | **지정가(Limit)** + **시장가(Market)** |
| 수수료 | 동적 수수료율 (서버 DB 설정, 기본 **1%**, 어드민이 0~50% 조정 가능) |
| 체결 모델 | Crank 기반 매칭 — 주문 등록(tx 성공) ≠ 즉시 체결 |

### 주문 프로세스
```
[주문 생성] → [ATA 확인/생성(setupTx)] → [wSOL 래핑(SOL 매도시)]
→ [fresh tx 획득] → [온디바이스 서명] → [제출] → [활성 주문 폴링]
```

### 시장가 주문 동작
| 사이드 | 가격 | 방식 |
|---|---|---|
| 매도 (Sell) | **0.01** (극저가) | 모든 매수 호가 매칭 |
| 매수 (Buy) | **999,999** (극고가) | 모든 매도 호가 매칭 |
| 만료 | **150 슬롯** (~60초) 후 자동 만료 | `timeInForce` + `expirySlots` |

### 신규 토큰 지정가 매수/매도
| 항목 | 내용 |
|---|---|
| 토큰 등록 | 어드민이 `tokens` 테이블에 mint, symbol, decimals 등록 |
| Manifest 상장 | 서버가 Manifest에서 **토큰/USDT 마켓**을 찾아 자동 연동 |
| 지정가 거래 | 사용자가 원하는 가격으로 매수/매도 주문 가능 |
| 체결 조건 | Crank가 실행되어 매칭되면 체결 — 서버 10초마다 상태 폴링 |

### ✅ 자동 Withdraw (핵심 기능)
| 항목 | 내용 |
|---|---|
| 트리거 | 주문 폴링 시 **체결(filled)** 상태 감지 |
| 조건 | 지갑이 **unlock 상태** (사용자가 PIN 입력 직후 또는 거래 중) |
| 동작 | Manifest vault에서 **USDT**를 사용자 ATA로 자동 인출 (PIN 재입력 불필요) |
| 효과 | **거래 체결 → USDT가 바로 사용자 지갑으로 들어옴** (vault에 머물지 않음) |
| 실패 시 | 수동 withdraw 가능 (lock 상태일 때는 자동 skip) |

### 주문 상태 폴링 (서버 크론)
| 항목 | 내용 |
|---|---|
| 주기 | **10초마다** |
| 체결 감지 | `fillDiscriminant` (8바이트 매직)로 tx 로그 파싱 |
| 만료 | 1시간 이상 submitted 상태 → 자동 `expired` 처리 |
| 취소 | Manifest DELETE API + fresh cancel tx |

### 주문 수량 입력
| 항목 | 내용 |
|---|---|
| 빠른 비율 | 25% / 50% / 75% / 100% 버튼 |
| 슬라이더 | 0~100% 전체 범위 (시안→보라 그라디언트) |
| 최대 매수 | `USDT 잔액 / 가격` |

| 정렬 | `createdAt` 내림차순 (최신순) |
| 페이징 | 커서 기반 무한 스크롤 (20개/페이지) |
