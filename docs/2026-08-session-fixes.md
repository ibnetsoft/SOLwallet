**수정:** 클라이언트 타임아웃 30초 → 45초로 확대, 실패 시 서버가 알려주는 구체적 사유를 그대로 노출하도록 변경.

### 4-3. **체결된 주문이 계속 "미체결"로 표시되는 핵심 버그** (`fbefd65`, `0cd5645`)
**현상:** SOL을 70.5에 매도 주문 → 온체인 오더북에서는 이미 사라졌는데(=체결됨) 앱에서는 계속 "미체결 주문"으로 표시됨. 실측 확인 결과 지갑에 인출 가능한 USDT 0.191248개가 온체인에 대기 중이었음(자금은 안전, 미인출 상태였을 뿐).

**원인 (2단계):**
1. 체결 감지가 "주문 제출 트랜잭션 자체의 로그"에서만 fill 이벤트를 찾고 있었음 — 이 방식은 주문 제출 즉시 자기 자신과 크로스되어 체결되는 경우만 감지 가능하고, **일반적인 경우(나중에 다른 트레이더가 체결시키는 경우)는 fill 이벤트가 상대방 트랜잭션 로그에 기록되므로 절대 감지 불가능**했음.
2. 1차 수정 후 추가로 발견: 1시간 타임아웃 체크가 체결 여부 확인보다 먼저 실행돼서, 실제로 체결된 주문도 생성된 지 1시간이 지나면 체결 확인을 타보지도 못하고 곧바로 `expired` 처리됨.

**수정:**
- tx 로그 확인(즉시체결 감지) → 온체인 오더북 대조(다른 트레이더에 의한 체결 감지)까지 2단계로 체결 여부 확인
- 타임아웃은 체결 증거를 못 찾았을 때만 적용하도록 순서 변경
- 마켓 조회는 폴링(10초 주기) 1회당 캐시해 중복 RPC 방지

## 5. PIN 입력 UX 개선 (`66605ea`, `09bf271`)

**요청 배경:** 거래할 때마다 PIN을 매번 입력해야 해서 불편하다는 피드백.

- 지갑이 이미 잠금 해제된 세션이면 **매수/매도 주문, 주문취소, 스왑**은 PIN 모달 없이 즉시 서명/제출
- 잠겨있을 때(세션 최초 1회)만 PIN 모달 표시 → 이후 계속 유지
- **출금(수익 인출)은 특수 케이스로 유지** — 이미 잠금 해제된 상태여도 매번 PIN 재확인
- 거래 활동 시 5분 자동잠금 타이머를 연장하는 `extendSession()` 추가 (활발히 거래 중엔 타임아웃으로 끊기지 않도록)
- 탭 숨김 시 즉시 잠금, 5분 비활동 시 자동 잠금은 기존과 동일 유지 (보안 백스톱)
- 스왑과 외부 출금(`WithdrawModal`, 홈 화면 "출금")은 이번 변경 대상 아님 — 외부 출금은 기존과 동일하게 매번 PIN 필요

## 6. 지갑 중복 생성 버그 수정 (`bea3b94`)

**현상:** 모바일에서 지갑을 만든 후 PC로 접속(같은 텔레그램 계정)하면 기존 지갑 대신 완전히 새로운 지갑이 또 생성됨.

**원인:** 홈 화면이 "지갑 0개 → 지갑 생성 페이지로 이동"을 판단할 때, 서버 동기화(`fetchWallets`)가 끝나기도 전에 **이 기기의 로컬 저장소만 보고 판단**하는 레이스 컨디션이 있었음. 새 기기는 로컬에 지갑 정보가 없으므로 서버에 이미 지갑이 있어도 항상 "0개"로 오판해 즉시 지갑 생성 화면으로 보내버렸고, 설정 페이지도 URL 파라미터(`?create=true`)만 믿고 검증 없이 생성 모달을 띄웠음.

**수정:** `walletsSynced` 플래그를 추가해 서버 동기화가 실제로 끝난 뒤에만 "지갑 0개" 판단을 내리도록 홈 화면·설정 페이지 양쪽에 이중 확인 추가.

> 참고: 텔레그램 ID(`telegram_uid`)는 DB에서 UNIQUE 제약이라 동일 ID로 재로그인해도 **유저 계정 자체가 중복 생성되지는 않음** — 이번에 실제로 중복됐던 건 계정이 아니라 지갑(로컬 키페어)이었음.

## 7. 신규 상장 토큰 거래 실패 근본 원인 수정 (`cf6811c` ~ `bc03fee`)

**현상:** 신규 상장 토큰(DUDE) 매도 시도 시 "트랜잭션 생성에 실패했습니다" → 이후 "거래 준비가 아직 반영되지 않았습니다. 잠시 후 다시 시도해주세요" 반복 → "거래소가 아직 이 토큰의 마켓 정보를 인식하지 못했습니다" 순으로 계속 실패.

원인은 서로 다른 두 가지가 순서대로 겹쳐 있었음. **DUDE 토큰 자체의 문제가 아니라, 신규 상장 토큰에서 처음 발생하는 계정 상태(지갑별) 문제였음** — 최종적으로 SOL/USDT 마켓에서도 동일 지갑이 똑같이 실패하는 것을 확인해 DUDE 전용 문제가 아님을 검증함.

### 7-1. Manifest Global 계정 미생성 (`cf6811c`)
**원인:** Manifest는 민트마다 "Global 계정"(PDA)이 있어야 주문 생성 API가 동작하는데, 신규 상장 토큰은 이게 아직 없어 API가 항상 500으로 실패. Global 계정은 사용자 서명이 있어야 생성 가능.

**수정:** 주문 생성 전 Global 계정 존재 여부를 확인(`findMissingGlobalMints`)해, 없으면 생성 트랜잭션을 먼저 클라이언트에 반환(`setupRequired: true`) → 사용자 서명·제출 → 주문 재요청 시 정상 진행되는 흐름 추가. SOL 부족으로 생성 트랜잭션 시뮬레이션이 실패하면 필요 금액을 구체적으로 안내(`3321bab`).

### 7-2. `finalized` commitment로 인한 재시도 실패 (`8196e18`)
**원인:** 위 setup 트랜잭션을 컨펌까지 기다린 뒤 재시도해도, 서버의 RPC 커넥션이 기본값 `finalized` 커밋먼트를 쓰고 있어 방금 만든 계정이 최대 30초간 "아직 없음"으로 보임 → 재시도가 계속 setup을 또 요구하는 무한루프.

**수정:** Global 계정 조회에 `'confirmed'` 커밋먼트를 명시.

### 7-3. 마켓 좌석(seat) 미보유 시 500 에러 (`bc03fee`) — 진짜 근본 원인
**원인:** Manifest 주문 생성 API(`/v1/orders`)는 `setupIxs:true`를 줘도, 트레이더가 해당 마켓에 **좌석(seat)**이 없으면 스스로 만들지 못하고 `Cannot read properties of null (reading 'publicKey')` 500 에러를 냄 (거래소 쪽 버그로 추정). 좌석은 Global 계정과 달리 **지갑×마켓 조합마다 개인이 각자 보유**해야 하는 계정.

**실측 검증:** 동일한 SOL/USDT 마켓에서 좌석 없는 지갑(mayersam) → 500 / 좌석 있는 지갑(Kmkill) → 200 정상. DUDE와 무관하게 재현되어 "특정 토큰 문제"가 아님을 확정.

**수정:**
- `getMarketSeatSetup()` 추가 — `ManifestClient.getSetupIxs()`로 좌석 필요 여부 확인
- 필요 시 좌석 생성 instruction을 기존 setup 트랜잭션(ATA/Global 생성과 동일 트랜잭션)에 함께 포함, wrapper 키페어는 서버가 미리 서명(pre-sign)
- 커넥션 전체의 기본 commitment를 `'confirmed'`로 변경 (7-2와 동일한 원리의 재발 방지)

**비용 (실측, mayersam의 좌석 생성 트랜잭션 기준):**

| 항목 | 비용 | 부담 주체 |
|---|---|---|
| Global 계정 (민트당 1개, 전원 공유) | 약 0.0016 SOL | 그 토큰의 진짜 최초 거래자 1명 |
| 마켓 좌석 (지갑×마켓별 1개, 개인 소유) | 0.000673 SOL (렌트 668,160 + 수수료 5,000 lamports) | 그 마켓 첫 거래하는 사람 본인 |

이제 신규 토큰 상장이든 기존 토큰에 신규 유저가 진입하는 경우든, 위 두 상황 모두 `createOrder` 흐름 안에서 자동 감지 → 준비 트랜잭션 서명 요청 → 재시도로 자동 처리되어 추가 개입이 필요 없음.

## 9. 출금·자산가치·체결·크래시 연쇄 수정 (`bc94a13` ~ `61eae7a`)

DUDE 실거래 테스트 중 연쇄적으로 발견된 문제들. 서로 인과관계가 있어 발견 순서대로 정리.

### 9-0. 클라이언트 크래시 리포팅 인프라 추가 (`bc94a13`)
"Application error: a client-side exception has occurred"라는 원인 불명 화면이 신고됐으나, mini-app에 크래시를 기록하는 장치가 전혀 없어(Sentry 등 미도입) 서버·nginx 로그 어디에도 흔적이 없었음.

**추가:** `app/error.tsx` / `app/global-error.tsx`가 렌더링 예외를 잡아 `POST /api/client-error`(인증 불필요)로 스택트레이스를 전송 → `docker compose logs server`에서 바로 확인 가능. 이후 모든 버그가 이 로그 덕분에 추측 없이 원인을 특정됨.

### 9-1. 출금 모달 클릭 시 크래시 (`7258a80`)
**원인:** React 에러 #310(Rendered more hooks than during the previous render). `WithdrawModal`의 `if (!isOpen) return null;`이 `useCallback`/`useEffect` 두 개보다 앞에 있어서, 모달이 닫힌 렌더(훅 N개)와 열리는 순간(훅 N+2개) 사이에 훅 호출 개수가 달라져 크래시.

**수정:** 두 훅을 early return보다 앞으로 이동.

### 9-2. 총자산·보유자산 시세 계산 (`11351a9`, `a0f1048`)
**현상:** 홈 화면 총자산이 SOL 시세만 반영(다른 토큰 잔액이 통째로 빠짐), Holdings 목록은 SOL·스테이블이 아닌 토큰을 전부 "1개 = $1"로 표시(DUDE 150개 → $150).

**원인:** `balance.service.ts`의 `totalUsdtValue`가 `0`으로 하드코딩된 미구현 TODO였고, 프론트도 실제 시세 없이 1:1 가정.

이어서 오더북 최우선호가 중간값으로 1차 수정했으나, DUDE처럼 유동성이 거의 없는 마켓에서 bestBid $1(먼지 수량) / bestAsk $19.07의 중간값 $10.0355가 나와 150개가 $1505로 표시되는 새 문제 발생 — 실제로 아무도 그 가격에 사고팔 수 없는 허수였음.

**최종 수정:** `PriceService.getTokenPrice(mint)` — 우리 DB에 기록된 최근 체결(filled) 주문의 price를 사용. 체결 이력이 없으면 0(임의 가정 안 함). 30초 캐시로 잔액 폴링 증폭 방지.

### 9-3. ROI 초기값 재설계 (`e0f7edd`)
**요청 배경:** 기존 "초기값"은 이 기기에서 앱을 처음 켰을 때 우연히 잡힌 총자산 스냅샷 하나(localStorage, 기기별로 다름) — 어떤 코인이 언제 얼마에 들어왔는지 전혀 반영 안 함.

**수정:** 지갑에 각 코인이 **최초로 입금된 시점**의 달러 가치를 코인별로 계산해 `wallet_deposit_baseline` 테이블(마이그레이션 009, 수동 실행 필요)에 영구 기록하고, 그 합계를 ROI 초기값으로 사용. 과거 시세 이력이 없어 최초 감지 시점의 현재가로 근사(스테이블은 1:1). 온체인 입금 이력은 `TransfersService.findFirstDeposits()`(신규)로 스캔. `withdrawnTotal`(ROI 제외용)도 서버의 `transfers` 테이블(외부 출금만 기록됨, Manifest 수익 인출은 미포함) 기준으로 계산해 기기 간 일관성 확보.

### 9-4. 체결된 주문이 영원히 "미체결"로 남는 버그 (`8454bbd`)
**현상:** DUDE $1 자가체결 테스트 중 재현. 체결 감지 자체는 10초마다 정확히 성공(로그에 "FILLED" 계속 찍힘)하는데, 화면엔 계속 취소 가능한 미체결 주문으로 남음.

**원인:** Manifest FillLog의 `baseAtoms`/`quoteAtoms`가 원시 숫자가 아니라 `{ inner: bignum }` 래퍼 객체로 역직렬화되는데, 이 unwrap 없이 바로 `toString()`을 호출해 `"[object Object]"` → `NaN`이 됨. 그 `NaN`이 DB의 `filled_qty`(NOT NULL)에 들어가려다 매 폴링마다 update 자체가 실패를 반복.

**수정:** `.inner`를 먼저 꺼내도록 수정 + `Number.isFinite` 이중 안전장치.

### 9-5. 체결 후 USDT 자동 인출이 거의 안 타던 문제 (`c1ef3f4`)
**원인:** 체결은 서버 백그라운드 폴러가 비동기로(주문 생성 후 한참 뒤에도) 감지하는데, 새로 체결된 주문을 감지해 자동 인출을 트리거하는 클라이언트 로직(`fetchOrderHistory`)이 거래 페이지 진입 시 딱 한 번만 호출됨.

**수정:** 거래 페이지에 15초 주기 폴링 추가.

### 9-6. Withdraw Profit 클릭 시 패닉 + PIN 정책 변경 (`afeb658`)
**원인:** Manifest wrapper 프로그램의 실제 Rust 소스(`withdraw.rs`)를 직접 확인해 특정. `trader_token_account.try_borrow_data()?[0..32]`로 ATA의 첫 32바이트(mint)를 그대로 읽는데, 그 토큰을 한 번도 받아본 적 없는 지갑은 ATA 자체가 온체인에 없어(데이터 길이 0) "range end index 32 out of range for slice of length 0"로 패닉. USDT를 한 번도 보유한 적 없는 지갑이 첫 USDT 인출을 시도할 때 재현됨.

**수정:** `getWithdrawTx`가 인출 전 base/quote 각 민트의 ATA 존재를 확인, 없으면 같은 트랜잭션에서 생성(`createOrder`에 이미 있던 패턴을 여기도 적용).

**PIN 정책 변경:** Withdraw Profit(Manifest 잔액 인출)은 외부로 자금이 나가는 게 아니라 이미 본인 소유 자금을 자기 지갑으로 옮기는 것뿐이라 위험도가 낮음 — 거래/취소와 동일하게 세션이 이미 잠금 해제 상태면 PIN 없이 즉시 실행되도록 변경. 외부 전송 출금(`WithdrawModal`)은 실제로 자금이 밖으로 나가므로 기존대로 매번 PIN 재확인 유지.

### 9-7. 거래화면 현재가 + Withdraw 버튼 아이콘화 (`61eae7a`)
**원인:** 9-2에서 홈 화면 자산가치는 "최근 체결가" 기준으로 고쳤지만, 거래 화면의 현재가(지정가 자동입력·시장가 실행가)는 여전히 클라이언트에서 직접 오더북 `(bestBid+bestAsk)/2`를 계산하고 있어 DUDE를 정확히 $1에 체결시킨 뒤에도 $10.0355로 표시됨.

**수정:** `PriceService.getTradePrice(mint)`(최근 체결가 우선, 체결 이력이 아예 없으면 오더북 중간값 폴백) + `GET /api/price/token/:mint` 신설. 프론트의 `fetchCurrentPrice`가 서버 위임으로 교체돼 홈 화면과 동일 기준 사용.

Withdraw Profit은 세션 unlock 상태면 자동 인출도 되므로, 텍스트 버튼 대신 입금 화살표 아이콘(수동 sweep 용도)으로 축소.

## 11. 스왑 컨펌 누락, 어드민 화면 정비, 유령 주문 근본 원인, PIN 세션 정책 (`fe6f78f` ~ `f5ddb2c`)

### 11-1. 스왑이 체인 미반영인데도 성공으로 표시 (`fe6f78f`)
**현상:** 0.0002 USDT → USDC 스왑에서 토스트에 "Tx: ..."까지 떴는데 홈 화면 USDT 잔액이 그대로. 서명을 직접 조회해보니 `getSignatureStatuses`가 계속 null — 트랜잭션이 온체인에 전혀 포함되지 않았음.

**원인:** `executeSwap`이 `sendTransaction`으로 전송만 하고 컨펌 대기 없이 바로 성공 응답. `sendTransaction`은 네트워크 전달만 보장할 뿐 블록 포함을 보장하지 않는데, 이 확인이 없어 블록해시 만료 등으로 조용히 드랍돼도 클라이언트는 성공 토스트를 봄. 출금 흐름(`submitWithdrawTx`)에는 이미 있던 컨펌 대기 로직이 스왑에만 빠져 있었음.

**수정:** `confirmTransaction`으로 컨펌 대기 후에만 성공 반환, `skipPreflight`/`maxRetries` 옵션 추가, 컨펌 실패 시 명확한 에러 반환.

### 11-2. 어드민 화면 정비
- **수수료 정산 페이지 "시간" 칼럼 중복 (`ed92a50`):** 헤더에 `시간` `<th>`가 두 번 있는데 데이터 행은 하나뿐이라 사용자 칼럼부터 전부 한 칸씩 밀려 표시 — 중복 헤더 제거.
- **대시보드 "오늘" 집계가 UTC 자정 기준이던 버그 (`e49d0cb`):** `new Date(); setHours(0,0,0,0)`가 컨테이너 시스템 타임존(UTC) 기준 자정을 계산해, 한국시간 오전 9시 이전 활동이 전부 "어제"로 빠짐. 오늘 가입·오늘 트랜잭션·오늘 입금액 전부 이 계산을 공유하고 있어 한 곳(`getKstTodayStart()`)만 고치면 전부 해결되는 구조였음.
- **취소 상태 색이 실패와 동일 (`c670089`):** 대시보드·트랜잭션 페이지에서 취소(cancelled)와 실패(failed)가 둘 다 빨강이라 구분 안 됨 — 취소를 주황색으로 변경.
- **전체 유저 입출금 내역 통합 + 정렬/필터 (`f3b27c4`, `1df2d50`):** 기존엔 지갑 주소를 하나씩 입력해야 입출금 내역을 볼 수 있었음(전체 유저 조회·정렬 불가). `TransfersService.getAllTransfers()` 신설 — 활성 지갑 전체를 온체인에서 스캔해 유저명과 함께 합쳐 반환(지갑당 최근 20건). 입금/출금 따로 보는 필터, 클릭 정렬 추가. 이후 트랜잭션 페이지의 주문 내역/입출금 내역을 위아래 배치 대신 상단 탭으로 전환.
- **대시보드에 오늘의 입출금 내역 섹션 (`4f3a9dc`):** 오늘의 입금액 섹션 아래에 `getAllTransfers`를 재사용하되 KST 오늘 자정 이후로 필터링해 실제 거래 목록 표시.

### 11-3. 체결된 주문이 영원히 "미체결"로 남는 근본 원인 (`ef9089b`, `d0a58a6`, `b522d7d`)
**현상:** 관리자 페이지에 tx 없이 "미체결"로 뜨는 주문 확인 요청 — 실제로는 서명이 끝내 실패해 거래소에 한 번도 전달된 적 없는 주문인데 영원히 "미체결"로 남고 취소도 안 됨(Manifest는 "no open orders"로 정확히 응답).

**원인 (2단계):**
1. `createOrder`가 Manifest에 unsigned tx 생성 요청을 보내 응답만 받으면 — 클라이언트 서명 여부와 무관하게 — 즉시 `status='active'`로 바꿔버림. 서명이 끝내 실패하면 tx_signature 없이 이 상태로 영구 정체되는데, 기존 정리 로직은 전부 tx_signature가 있는 주문만 조회해 이 케이스를 못 봄.
2. 별개로, 다른 트레이더가 나중에 체결시키는 일반적인 경우를 감지하는 2단계 검사(`isOrderStillOpen`)도 `manifest_sequence_number`가 코드 어디서도 채워진 적이 없어(항상 NULL) 지금까지 단 한 번도 실행된 적이 없었음.

**수정:**
- `checkOrphanedPendingOrders()` 추가 — status IN (pending, active) + tx_signature 없음 + 5분 경과 주문을 failed로 자동 정리.
- Manifest가 주문 생성 시 로그에 남기는 `PlaceOrderLog` 이벤트에서 `orderSequenceNumber`를 추출해 저장(`extractOrderSequenceNumber`) — 이제 2단계 체결 감지가 정상 동작.
- 클라이언트 서명 실패 메시지도 "유효하지 않은 트랜잭션입니다" → 원인·재시도 안내가 담긴 문구로 변경(4개 언어).
- 서명 실패 원인을 서버로 보고하는 `reportClientError()` 추가(`f8b6622`) — 이후 재현 시 서버 로그에서 바로 원인 확인 가능.

### 11-4. 거래화면 가격 표시 소수점 절사 (`5523d4a`)
오더북 가격을 `String(price)`로 그대로 입력창에 넣다 보니 `76.26493955000001` 같은 부동소수점 결과가 노출됨. `truncateDecimals()` 추가 — 소수점 8자리까지만 남기고 반올림 없이 절사. 지정가 자동입력 4곳 전부 적용.

### 11-5. 지갑 삭제 PIN 확인 (`fac1717`)
지갑 삭제가 브라우저 confirm() 한 번으로 바로 실행되던 것을 PIN 검증 후에만 삭제되도록 변경. 다른 기기에서 만든 지갑이라 이 기기에 로컬 키가 없는 경우는 검증할 PIN 자체가 없으므로 기존처럼 confirm()만 유지.

### 11-6. PIN 세션 정책 확정 (`4341b80`, `f5ddb2c`)
매수/매도/수익인출(Withdraw Profit)은 세션 유지 시 PIN 재입력 없이 진행, 외부 출금(WithdrawModal)과 지갑삭제는 항상 PIN 재확인 — 이 구분은 이미 구현되어 있었고, 이번엔 세션 자체의 정책만 조정:
- 자동 잠금 유지 시간 5분 → **2시간**으로 연장 (`AUTO_LOCK_TIMEOUT`).
- 탭/앱이 백그라운드로 전환되면(`visibilitychange`) 즉시 잠그던 로직 제거 — 다른 화면 갔다 와도 2시간 타이머 안에서는 세션 유지.
  ⚠️ 트레이드오프: 지갑 개인키가 그만큼 더 오래 메모리에 남아있음 — 사용자 요청으로 명시적으로 반영.
